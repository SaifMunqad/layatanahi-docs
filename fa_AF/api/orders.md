# سفارش‌ها

`GET /api/v2/orders` سفارش‌های بین‌شعبه‌ای دیدنی برای تجارت را برمی‌گرداند. یک سفارش سندی است که یک خرید یا فروش میان شعبه‌ها را پیش می‌گیرد؛ یک وضعیت، یک شماره پیگیری و مجموع‌های فاکتور را حمل می‌کند.

## اجازه

| الزام | مقدار |
| --- | --- |
| صلاحیت | `orders:read` |
| اجازه صفحه | `sale.orders.read` |
| رفتار شعبه | سطح کل تجارت یا شعبه‌فیلترشده |

## پارامترهای کوئری

| پارامتر | نوع | پیش‌فرض | یادداشت |
| --- | --- | --- | --- |
| `from` | date | — | شروع شامل، بر اساس ایجاد سفارش |
| `to` | date | — | پایان شامل؛ باید برابر یا بعد از `from` باشد |
| `status` | enum | — | یکی از وضعیت‌های پشتیبانی‌شده |
| `page` | integer ≥ 1 | 1 | شماره صفحه |
| `per_page` | integer 1–100 | 25 | اندازه صفحه |

مقدارهای وضعیت پشتیبانی‌شده: `pending`، `deleted`، `shipped`، `completed`، `approved`، `denied`. هر مقدار دیگر با `422` رد می‌شود.

## درخواست

```bash
curl -s "https://app.example.com/api/v2/orders?status=pending&from=2026-10-01" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Business-Branch: 4" \
  -H "Accept: application/json"
```

## پاسخ

```json
{
  "data": [
    {
      "id": 88,
      "business_branch_id": 4,
      "order_number": "ORD-2026-0088",
      "tracking_number": "TRK-99120",
      "status": "pending",
      "invoice_number": "INV-2026-7781",
      "grand_total": 18500.0,
      "paid_amount": 0.0,
      "created_at": "2026-10-24 09:02:11"
    }
  ],
  "meta": { "current_page": 1, "last_page": 1, "per_page": 25, "total": 1 }
}
```

## فیلدها

| فیلد | معنا |
| --- | --- |
| `id` | شناسه سفارش |
| `business_branch_id` | شعبه‌ای که در طرف شما از سفارش است |
| `order_number` | مرجع سفارش قابل‌خواندن برای انسان |
| `tracking_number` | مرجع پیگیری حمل‌کننده یا داخلی، وقتی موجود باشد |
| `status` | وضعیت فعلی سفارش |
| `invoice_number` | فاکتور مرتبط با سفارش |
| `grand_total`, `paid_amount` | مجموع‌های فاکتور به ارز فاکتور |
| `created_at` | زمان‌برچسب ایجاد سفارش |

پاسخ اقلام سفارش را دربر ندارد. برای جزئیات سطح قلم از رابط وب یا نقاط پایانی خرید و فروش استفاده کنید.

## معنای وضعیت‌ها

| وضعیت | معنا |
| --- | --- |
| `pending` | ایجاد شده و در انتظار یک تصمیم |
| `approved` | توسط شعبه دریافت‌کننده پذیرفته شده |
| `shipped` | ارسال بار انجام شده |
| `completed` | تکمیل و بسته شده |
| `denied` | توسط شعبه دریافت‌کننده رد شده |
| `deleted` | نرم‌حذف‌شده اما همچنان توسط فیلتر گزارش می‌شود |

`deleted` فقط وقتی ظاهر می‌شود که صریحاً درخواست شود. آن سفارشی را نمایندت می‌کند که از استفاده فعال بیرون رفته است؛ آن را یک حالت تکمیل تلقی نکنید.

## هم‌خوانی شعبه

یک سفارش وقتی برگردانده می‌شود که یکی از طرف‌ها به یک شعبه دیدنی تعلق داشته باشد:

- فاکتور توسط یک شعبه دیدنی صادر شده، یا
- فاکتور به یک شعبه دیدنی نشانی رفته است.

`business_branch_id` شعبه طرف شما را گزارش می‌کند. وقتی یک اعتبارنامه به یک شعبه محدود شده، فقط سفارش‌های درگیر همان شعبه ظاهر می‌شوند.

## ترتیب

سفارش‌ها جدیدترین اول بر اساس زمان ایجاد برگردانده می‌شوند، که همگام‌سازی تدریجی را ساده می‌سازد: صفحه اول را درخواست کنید و وقتی به سفارشی رسیدید که از قبل ذخیره‌اش دارید متوقف شوید.

## استفاده‌های رایج

| استفاده | روش |
| --- | --- |
| صف سفارش‌های وارده | `status=pending` را برای شعبه فیلتر کنید |
| پیگیری محموله | `tracking_number` سفارش‌های `shipped` را بخوانید |
| مغایرت‌گیری بین‌شعبه‌ای | مجموع‌های سفارش را با خرید یا فروش مرتبط مقایسه کنید |
| خلاصه روزانه | `from` امروز را درخواست کنید، بر اساس وضعیت گروه‌بندی کنید |

## محدودیت‌ها

- فقط‌خواندنی: سفارش‌ها از طریق API نمی‌توانند ایجاد، پذیرفته یا حذف شوند.
- اقلام سفارش دربر گرفته نمی‌شوند.
- مبلغ‌ها به ارز فاکتور و بدون تبدیل‌اند.
- سفارش‌های بیرون از دامنه شعبه دیدنی به‌طور کامل مستثنا می‌شوند.
