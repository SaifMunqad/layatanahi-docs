# پاڼه‌بندي او فلټر

هره د لیست ننوتنه د معیاري Laravel د پاڼه‌بندي لفافې سره پاڼه‌بندي کېږي. تفصیلي ننوتنې پاڼه‌بندي
نه کېږي؛ دوی یو واحد `data` څیز راوړي.

ځکه چې ټولګې کیدای شي لویې وي، ادغامونه باید په ډاډمنه توګه پاڼې وګرځوي او د کرښې د ځای‌تکیه پر ځای یوه
باثباته بهرنۍ کیلي وساتئ.

## پارامترونه

| پارامتر | ډول | ډیفالټ | اعظمي | پلي کېږي پر |
| --- | --- | --- | --- | --- |
| `page` | integer | 1 | — | ټول لیستونه |
| `per_page` | integer | 25 | 100 | ټول لیستونه |

هغه ارزښتونه چې د منل شوي حد څخه بهر وي `422` د تصدیق (validation) ځواب رامنځته کوي. کسري یا غیر
عددي ارزښتونه نه پرېښودل کېږي، بلکې ردېږي.

## لفافه

```json
{
  "data": [],
  "links": {
    "first": "https://app.example.com/api/v2/sales?page=1",
    "last": "https://app.example.com/api/v2/sales?page=4",
    "prev": null,
    "next": "https://app.example.com/api/v2/sales?page=2"
  },
  "meta": {
    "current_page": 1,
    "from": 1,
    "last_page": 4,
    "per_page": 25,
    "path": "https://app.example.com/api/v2/sales",
    "to": 25,
    "total": 87
  }
}
```

| د meta فیلډ | معنا |
| --- | --- |
| `current_page` | هغه پاڼه چې په دې ځواب کې راغلې |
| `last_page` | تر ټولو وروستۍ پاڼه چې د هغو فلټرونو لپاره شته |
| `per_page` | پلي شوې د پاڼې کچه |
| `from`, `to` | په دې پاڼې کې د کرښو محدوده؛ کله چې پاڼه خالي وي `null` |
| `total` | هغه ټولې کرښې چې د فلټرونو سره سمون خوري |
| `path` | اساسي URL، پرته له پوښتنې پارامترونو |

`links.prev` او `links.next` په پولو کې `null` وي. تر هغه `next` تعقیب کړئ چې `null` نه وي شوی؛ د پاڼې
شمېره په ډېرې پام‌ورکړې سره مه زیاتوئ، ځکه د فلټرونو ټولګه ستاسو لاندې بدلېدای شي.

## د پوښتنې تارونه ساتل کېږي

د پاڼه‌بندي لینکونه ستاسو فلټرونه ساتي. غوښتنه چې `from=2026-10-01&status=pending` ولري، لینکونه جوړوي چې هغه پارامترونه لا هم لري، چې "د راتلونکي لینک تعقیب" کول خوندي کوي.

## ترتیب

| سرچینه | ترتیب |
| --- | --- |
| محصولات | `id` صعودي |
| ذخیره | د ذخیرې `id` صعودي |
| پېرودونه | له نوې څخه زوړ |
| پلورونه | له نوې څخه زوړ |
| فرمایشونه | `created_at` نزولي |

د یوه ثابت ډاټا سیټ لپاره ترتیب باثباته دی. که ریکارډونه د پاڼو په اوږدو کې دننه شي، د تدریجي همغږۍ
لپاره د پاڼو د نمرو پر ځای د نېټې فلټر یا د "جوړ شوی وروسته" واټرمارک وکاروئ.

## د تدریجي همغږې کولو نمونه

1. لومړۍ پاڼه داسې ولولئ چې `from` ستاسو د وروستي بریالي واټرمارک ته ټاکل شوی وي.
2. کرښې پروسس کړئ، او د سرچینې `id` او `created_at` وساتئ.
3. واټرمارک هغه نوي `created_at` ته انتقال کړئ چې پروسس مو کړی وي.
4. که نوې کرښه دمخه پیژندل شوې وي، وروسته له لومړۍ پاڼې ودروئ.

دا تکرارونه مخنیوي او د غوښتنو شمېر ټیټ ساتي.

## د فلټرونو لنډیز

| ننوتنه | شتون ولرونکي فلټرونه |
| --- | --- |
| `/api/v2/products` | `search`, `language_code` |
| `/api/v2/stock` | `language_code` (څانګه د سرلیک له لارې) |
| `/api/v2/purchases` | `from`, `to`, `language_code`, `id` |
| `/api/v2/orders` | `from`, `to`, `status` |
| `/api/v2/sales` | `from`, `to`, `language_code`, `id` |

## د نېټو فلټرونه

- بڼه: `YYYY-MM-DD`.
- دواړه پولې شاملې دي.
- `to` باید له `from` سره مساوي یا وروسته وي.
- د دواړو پولو پرېښودل ټوله تاریخچه له نوې څخه زوړ راوړي.
- نېټې د اپلیکېشن د وخت سیمې (timezone) په اساس تفسیروېږي؛ په ځوابونو کې وختونه ذخیره شوي ارزښتونه دي،
  نو هغوی په یو شان ډول پرتله کړئ.

## د پاڼې د کچې ټاکل

| موخه | سپارښتنه شوې `per_page` |
| --- | --- |
| تعاملي لټون | 10–25 |
| شپنۍ همغږي | 100 |
| د پرتله‌کولو صادرول | 100 د نېټو د کړکۍ سره |

لویې پاڼې د هر ریکارډ لپاره کمه کوټه لګوي، ځکه کوټه پر غوښتنه اخیستل کېږي، نه پر کرښه.
