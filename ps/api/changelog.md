# د بدلونونو یادښت

دا پاڼه د سوداګرۍ API او د MCP سرور بدلونونه ثبتوي. نېټې د خپرېدو تقریبي کړکۍ دي؛ هغه چلند چې په
دې اسنادو کې تشریح شوی، اوسنی خپرېدو ښیي.

## د نسخه‌بندۍ تګلاره

- ملاتړ شوې د ادغام سطحه `/api/v2` او `/mcp/business` ده.
- اضافي بدلونونه (نوي فیلډونه، نوي اختیاري فلټرونه) کیدای شي په v2 کې خپرېږي.
- ماتوونکي بدلونونه نوې نسخه غواړي.
- `/api/v1` د اپلیکېشن دننه سطحه ده او دا تګلاره پرې پلي نه کېږي.

## اوسنی خپرېدو

### Business API v2

- یوازې د لوستلو ننوتنې: `context`, `products`, `stock`, `purchases`, `purchases/{id}`, `orders`,
  `sales`, `sales/{id}` او `health`.
- پنځه د لوستلو وړتیاوې: `products:read`, `stock:read`, `purchases:read`, `orders:read`, `sales:read`.
- د کارکوونکي سره نښلول شوې اعتبارنامې، چې په هره غوښتنه کې ژوندی رول او ګډون بیا تاییدوي.
- د څانګې ټاکل د `X-Business-Branch` له لارې، د یوې ورکړل شوې څانګې لپاره اتوماتیک ټاکل، او
  `422 branch_required` کله چې څو څانګې ورکړل شوې وي او هیڅ یوه نومول شوې نه وي.
- پاڼه‌بندي د `page` او `per_page` (1–100، ډیفالټ 25) سره، او هغه لینکونه چې فلټرونه ساتي.
- د ژبې له مخې د محصولاتو نومونه د `language_code` له لارې، چې د محصول کوډ ته راګرځي.
- د پېرود او پلور تفصیلي سرچینې، د بل، مقابل لوري، کرښو او تادیو سره.
- د فرمایشونو لیست د نېټې او حالت فلټرونو سره.

### کوټې او محدودیتونه

- د فج محدودونکی: په هر دقیقه کې د هرې اعتبارنامې لپاره 60 غوښتنې.
- کوټه: په ورځ کې 200 غوښتنې او په میاشت کې 2,000 پر کاروونکي.
- پلانونه: Free (1×)، Growth (3×)، Scale (10×)، Enterprise (50×)، د وخت محدود، د پای ته رسیدو
  راګرځېدو سره.
- `429` ځوابونه `Retry-After` لري، او د کوټې لپاره ساحه، موده، حد، کارول شوی شمېر او د بیا پیل وخت.

### د اعتبارنامو مدیریت

- جوړول، نوم بدلون، څرخول او بېرته اخیستل له **ترتیبات > API ادغامونه** څخه.
- د پټ کوډ یو‌ځلي ښکارېدنه؛ یوازې هاش ذخیره کېږي.
- د ټولې سوداګرۍ یا د ټاکلو څانګو ساحه.
- د مدیر لید د ټولې سوداګرۍ په کچه؛ مدیران یوازې خپلو اعتبارنامو ته محدود دي.
- د کارونې کارت د پلان، ضریب، کارونې، د بیا پیل وختونو او وروستیو پایلو سره.

### د MCP سرور

- `BusinessApiServer` په `POST /mcp/business` کې د Streamable HTTP له لارې وړاندې کېږي.
- پنځه وسیلې: `products`, `stock`, `purchases`, `orders`, `sales`.
- د وسیلو ګډ پارامترونه: `id`, `branch_id`, `per_page`, `page`, `language_code`.
- یوازې محلي (local-only) سندباکس په `/mcp/test` او `/mcp/business/test` کې، په محلي او ازموینیز
  چاپېریالونو کې.
- همغه د اعتبارنامې، وړتیا، څانګې او کوټې پروسه چې د HTTP API لپاره ده.

## پلان شوي او د بیا کتنې لاندې

دا توکي اوس مهال شتون نلري او ادغام باید پرې تکیه ونه کړي:

| توکی | حالت |
| --- | --- |
| د امضاوو سره بهرني ویب‌هوکونه | شتون نلري |
| د لیکلو ننوتنې (پلور، پېرود، تادیې) | شتون نلري؛ په ډیزاین کې یوازې لوستل |
| نورې سرچینې (حسابونه، فعالیتونه، راګرځېدنې) | شتون نلري |
| د هرې اعتبارنامې جلا د کوټې ټوکونه | کوټه پر کاروونکي ده |
| د API v3 نسخه | اعلان نه دی شوی |

## تقاعد شوي شيان

هېڅ v2 ننوتنه تقاعد شوې نه ده. که یو فیلډ یا ننوتنه له منځه ولاړه شي، دا پاڼه به یې نوم واخلي،
بدیل به یې وښيي، او د لرې کولو دمخه به د لیږد یوه موده ورکړي.

## څنګه ځان اوسنی وساتئ

1. له لوړولو (upgrade) وروسته بیا [د ننوتنو مرجع](/docs/api/reference) ولولئ.
2. د خپل ادغام قرارداد ازموینې د یوې ازموینیزې (staging) سوداګرۍ پر وړاندې چلوئ.
3. اضافي فیلډونه تعقیب کړئ؛ هغوی بدلون نه غواړي خو کیدای شي ګټر وي.
4. توپیرونه د خپل ملاتړ چینل له لارې راپور کړئ، نه دا چې پرې له هغوی څخه تېر شئ.
