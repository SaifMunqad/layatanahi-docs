# د API لنډه کتنه

د سوداګرۍ API ستاسو د سوداګرۍ ډاټا بهرنیو سیسټمونو ته خلاصوي: یو ERP، د راپور ورکولو یوه وسیله، د ګودام
سکینر یا یو AI مرستیال. دا په عمدي ډول **یوازې د لوستلو** دی. په API کې هېڅ شی نشي کولی ریکارډ جوړ کړي،
سم کړي، تادیه کړي یا ړنګ کړي، نو یو ادغام کولی شي ډاټا همغږې کړي پرته له دې چې ستاسو کتابونه بدل کړي.

دوه د HTTP سطحې شته، او همدارنګه د MCP سرور، او یوازې v2 د درېیمو اړخونو د پیرودونکو لپاره ډیزاین شوی دی:

| سطحه | لار | کاروونکي | حالت |
| --- | --- | --- | --- |
| د سوداګرۍ API v2 | `/api/v2` | بهرني ادغامونه چې یوه اعتبارنامه کاروي | ملاتړ شوی |
| Model Context Protocol | `/mcp/business` | AI پیرودونکي چې همغه اعتبارنامه کاروي | ملاتړ شوی |
| د اپلیکېشن API v1 | `/api/v1` | پخپله د Layatanahi ویب اپلیکېشن | دننی |

د v1 لارې د اپلیکېشن خپلې هغه ننوتنې دي چې براوزر ته خدمت کوي: AI مرستیال، چټبوټ، د خبرتیاوو فید، د
اسعارو نرخونه او د محصولاتو مرستیالې دندې. دا د ویب غونډې په چاپېریال کې پلي کېږي، د کاروونکي د انټرفېس
لپاره بڼل شوې دي، او پرته له خبرتیا بدلیږي. پر v1 باندې ادغام مه جوړوئ؛ v2 یا MCP وکاروئ.

## هغه څه چې API یې لوستلی شي

د v2 سطحه په دقت سره هغه سرچینې خپروي چې بهرني سیسټم یې غواړي. بل ډول ډاټا نشته.

| ننوتنه | څه شی راوړي | وړتیا |
| --- | --- | --- |
| `/api/v2/context` | د اعتبارنامې سوداګري، د رول ساحه، څانګې او کوټه | هره سمه اعتبارنامه |
| `/api/v2/products` | د محصولاتو کټالوګ، په کوډ، ماډل یا نوم سره لټون وړ | `products:read` |
| `/api/v2/stock` | د ذخیرې کرښې د شته، ترلاسه شوي او خوندي شوي مقدارونو سره | `stock:read` |
| `/api/v2/purchases` او `/api/v2/purchases/{id}` | د پېرود بلونه او د پېرود بشپړ تفصیل | `purchases:read` |
| `/api/v2/orders` | د څانګو ترمنځ فرمایشونه د حالت او ټولګې ارزښتونو سره | `orders:read` |
| `/api/v2/sales` او `/api/v2/sales/{id}` | د پلور بلونه او د پلور بشپړ تفصیل | `sales:read` |
| `/api/v2/health` | د خدمت روغتیا، پرته له کومې اعتبارنامې | هېڅ |

هر څه د یوهې سوداګرۍ سره محدودېږي. د بلې سوداګرۍ ریکارډونه هېڅکله نه ښکاري، که څه هم د هغې پېژندونکی
واړاندې کړئ. د حسابونو، معاشونو، کارکوونکو، رولونو یا ترتیباتو لپاره هېڅ ننوتنه نشته.

## تصدیق هویت څنګه کار کوي

یو ادغام جلا حساب نه دی. دا د یوه کارکوونکي له خوا صادره شوې اعتبارنامه ده، په هماغه کارکوونکي نښلول شوې،
او د هغه د کارکوونکي د ژوندي صلاحیتونو له مخې محدوده کېږي:

1. اجازه لرونکی کارکوونکی **ترتیبات > API ادغامونه** پرانیزي او یوه نوم لرونکې اعتبارنامه جوړوي.
2. اعتبارنامه یو Sanctum ټوکن او د لوستلو د وړتیاوو یوه ټولګه ترلاسه کوي.
3. هره غوښتنه بیا کتنه کوي چې سوداګري فعاله ده، کاروونکی لا هم په سوداګرۍ کې د کارکوونکي فعال ګډون لري،
   او کارکوونکی لا هم د مدیر یا اداري واک او هغه پاڼې ته صلاحیت لري چې د هغې وړتیا تر شا پروت دی.
4. که کارکوونکی له دندې لرې، له مدیریت څخه ښکته یا له اړوند صلاحیت څخه بې برخې شي، اعتبارنامه په راتلونکې
   غوښتنه کې په کلک ډول بندېږي.

وګورئ [تصدیق هویت](/docs/api/authentication) او [API کلیدونه او صلاحیتونه](/docs/api/api-key).

## د سوداګرۍ مدیر او د څانګې مدیر توپیر

واک یوازې له اعتبارنامې څخه نه، بلکې د کارکوونکي له ژوندي رولونو څخه اخیستل کېږي:

| واک | څنګه پېژندل کېږي | د څانګو پوښښ |
| --- | --- | --- |
| د سوداګرۍ مدیر | د سوداګرۍ ساحې رول چې `settings.write` پرې شامل وي | د سوداګرۍ ټولې فعالې څانګې |
| د څانګې مدیر | هغه څانګې چې هغه یې مدیریت کوي، یا د څانګې ساحې `Management` رول | یوازې خپلې مدیریت شوې څانګې |
| دواړه نه | نه مدیر او نه اداري واک | اعتبارنامه ردېږي |

هغه اعتبارنامه چې داسې کارکوونکي پورې اړه لري چې د واک هیڅ بڼه یې نه لري، ردېږي. له همدې امله د API لاسرسی
هغه رولونه تعقیبوي چې تاسو یې په انټرفېس کې مدیریت کوئ.

## د څانګې ساحه

یوه سوداګري کولی شي څو څانګې ولري. یوه اعتبارنامه یا د ټولې سوداګرۍ وي یا ټاکلو څانګو ته محدوده، او یوه
غوښتنه کولی شي یوې څانګې ته ونیول شي:

```http
GET /api/v2/sales?from=2026-10-01&to=2026-10-31
Authorization: Bearer <token>
X-Business-Branch: 4
```

- یوه **د ټولې سوداګرۍ** اعتبارنامه چې د څانګې سرلیک نه لري، د ټولو فعالو څانګو څخه لولي.
- هغه اعتبارنامه چې ساحه یې په دقیق ډول یوې څانګې ته محدوده ده، هماغه څانګه په اتوماتیک ډول کاروي.
- هغه اعتبارنامه چې ساحه یې څو څانګې پوښي، باید هدف څانګه یې وومعلوم کړي، په بل صورت API `422` ځوابوي.

## د غوښتنې له بریالیتوب دمخه اړتیاوې

| اړتیا | پلي کول |
| --- | --- |
| فعاله اعتبارنامه | حالت `active` او د ټوکن د کاروونکي له خوا مالکیت |
| فعاله سوداګري | سوداګري نه ده ړنګه شوې او `business_status = active` |
| فعال ګډون | کاروونکی لا هم په سوداګرۍ کې کارکوونکی دی |
| ژوندی واک | کارکوونکی د سوداګرۍ مدیر یا د څانګې مدیر دی |
| د څانګې ساحه | هغه اعتبارنامې چې د ټولې سوداګرۍ نه دي، باید لږ تر لږه یوه څانګه وساتي |
| وړتیا + صلاحیت | د ټوکن وړتیا او پاڼې ته ورکړل شوی اړوند صلاحیت |

که له دې څخه هر یو ناکام شي، غوښتنه نيمګړې ډاټا نه، بلکې د تصدیق هویت یا د اجازې تېروتنه راوړي.

## د ډیزاین اصول

- **د هوکړې له مخې یوازې لوستل.** د لیکلو هېڅ ننوتنه نشته، او وړتیاوې هم له همدې امله `:read` بلل کېږي.
- **لږ تر لږه صلاحیت.** یوازې هغه وړتیاوې ورکړئ چې ادغام ته یې اړتیا ده، او یوازې هغه څانګې چې خدمت یې کوي.
- **ژوندۍ اجازه.** صلاحیتونه په هره غوښتنه کې ارزول کېږي، نه د ټوکن د جوړولو پر مهال ثبتېږي.
- **د کوټې پوهاوی.** هره غوښتنه د یوه کاروونکي د ورځني او میاشتنۍ اجازې او د لنډمهاله فج (burst) له حد سره
  شمېرل کېږي؛ وګورئ [د نرخ محدودیتونه او کوټې](/docs/api/rate-limits).
- **باثباته نسخه‌بندي.** ماتوونکي بدلونونه نوې نسخې ته ځي؛ اضافي فیلډونه کولی شي په v2 کې راښکاره شي.
- **وړاندوینه وړ بڼې.** لیستونه د پاڼه‌بندي لفافې راوړي؛ تفصیلي سرچینې یو `data` څیز راوړي.
