# تصدیق هویت

د API v2 او MCP هره غوښتنه د یوه Sanctum بېرر ټوکن سره تصدیقېږي چې د **سوداګریز ادغام اعتبارنامې** پورې
اړه لري. ټوکن اعتبارنامه پېژني؛ اعتبارنامه سوداګري او کارکوونکی پېژني؛ او د کارکوونکي ژوندي رولونه
ټاکي چې غوښتنه څه شی لوستلی شي.

له همدې امله تصدیق هویت په یو ځای کې دوه کتنې دي: سم ټوکن، او لا هم سم د اجازې چاپېریال.

## د ټوکن لېږل

```http
GET /api/v2/context HTTP/1.1
Host: app.example.com
Authorization: Bearer 12|secret-token-value
Accept: application/json
```

قواعد:

- ټوکن د `Authorization` سرلیک له لارې، د `Bearer` پلان سره ولېږئ.
- تل `Accept: application/json` ولېږئ؛ پرته له دې، د چوکاټ تېروتنې د HTML په بڼه ښکارېږي.
- ټوکن د اعتبارنامې د جوړولو یا څرخېدو پر مهال یوازې **یو ځل** ښودل کېږي. هغه د پټو کلیدونو په مدیر کې وساتئ.
- ټوکنونه په ټاکلي وخت نه ختمېږي، خو هېره‌برېه چې اعتبارنامه بېرته واخیستل شي یا مالک کارکوونکی اړین واک
  له لاسه ورکړي، سمدلاسه بندېږي.

## سرور څه شی تاییدوي

د هرې غوښتنې لپاره، په دې ترتیب سره:

| ګام | کتنه | د تېروتنې کوډ |
| --- | --- | --- |
| 1 | د یوه Sanctum ټوکن شتون چې د ادغام پېژندونکي لري | `integration_credential_required` (401) |
| 2 | اعتبارنامه `active` ده او د ټوکن د کاروونکي له خوا ده | `integration_credential_invalid` (401) |
| 3 | سوداګري شته، نه ده ړنګه شوې او `active` ده | `integration_credential_invalid` (401) |
| 4 | کاروونکی لا هم په سوداګرۍ کې د کارکوونکي فعال ګډون لري | `integration_membership_inactive` (403) |
| 5 | کارکوونکی د سوداګرۍ مدیر دی یا لږ تر لږه یوه څانګه مدیریت کوي | `integration_role_revoked` (403) |
| 6 | هغه اعتبارنامه چې د ټولې سوداګرۍ نه ده، لا هم ساحه کې څانګه لري | `integration_branch_scope_empty` (403) |
| 7 | وړتیا ورکړل شوې ده، او ژوندی رول اړوند صلاحیت هم ورکوي | `api_ability_denied` (403) |
| 8 | غوښتل شوې څانګه د اعتبارنامې په ساحه کې ده | `branch_scope_denied` (403) یا `branch_required` (422) |

4 او 6 ګامونه له هر ډول ډاټا لاسرسي دمخه پلي کېږي. که کارکوونکی له دندې لرې شوی وي، له مدیریت څخه
لیږدول شوی وي، یا اړوند رول یې لرې شوی وي، اعتبارنامه بندېږي که څه هم د ټوکن متن لا هم سم دی.

## ژوندی واک

واک په هره غوښتنه کې د کارکوونکي له رولونو څخه اخیستل کېږي:

| واک | د پېژندلو لار |
| --- | --- |
| د سوداګرۍ مدیر | د سوداګرۍ ساحې رول چې `settings.write` پرې شامل وي |
| د څانګې مدیر | هغه څانګه چې کارکوونکی پکې مدیر دی، یا اصلي څانګه د څانګې ساحې `Management` رول سره |
| بې واکه | پورته هیڅ یو نه وي، نو `integration_role_revoked` راځي |

د سوداګرۍ د مدیر ساحه د سوداګرۍ ټولې فعالې څانګې دي. د څانګې د مدیر ساحه هغه څانګې دي چې هغه یې
مدیریت کوي. هغه اعتبارنامه چې ټاکلو څانګو ته محدوده ده، د کارکوونکي د مدیریت شوو څانګو او د اعتبارنامې
د ټاکلو څانګو ترمنځ په ګډو (intersection) ارزښتونو محدوده کېږي.

## د وړتیا او صلاحیت تطبیق

وړتیا په اعتبارنامې کې ورکول کېږي، خو هغه یوازې هغه وخت کار کوي چې د کارکوونکي ژوندی رول اړوند پاڼې ته
صلاحیت هم ورکړي:

| وړتیا | اړین د پاڼې صلاحیت |
| --- | --- |
| `products:read` | `inventory.products.read` |
| `stock:read` | `inventory.branches.read` |
| `purchases:read` | `purchase.purchases.read` |
| `orders:read` | `sale.orders.read` |
| `sales:read` | `sale.sales.read` |

د واک د لوړولو سطحې په عمدي ډول بهر دي: هېڅ وړتیا `access.*`، د کارکوونکو مدیریت، د پټنوم بدلون یا
دوه‌مرحله‌ای ترتیباتو ته نه تطبیقېږي.

## د څانګې ټاکل

هدف څانګه، په دې ترتیب سره، له دې ځایونو څخه ټاکل کېږي:

1. د `X-Business-Branch` سرلیک.
2. د MCP د یوه وسیلې د غوښتنې `branch_id` آرګومنټ.
3. د غوښتنې `branch_id` پارامتر.

بیا:

- که څانګه ورکړل شوې وي، هغه باید د سوداګرۍ وي او د اعتبارنامې په ساحه کې وي؛ په بل صورت `branch_scope_denied`.
- که څانګه نه وي ورکړل شوې او اعتبارنامه د ټولې سوداګرۍ وي، غوښتنه د ټولې سوداګرۍ له څانګو لولي.
- که څانګه نه وي ورکړل شوې او ساحه کې یوازې یوه څانګه وي، هماغه څانګه کارول کېږي.
- که څانګه نه وي ورکړل شوې او څو څانګې په ساحه کې وي، API `branch_required` ځوابوي.

## د ټوکن جلا والی

د ادغام ټوکنونه یوازې په `/api/v2/*` او `/mcp/*` کې منل کېږي. که یو ټوکن په بل Sanctum‌حفاظت شوې لاره
وکارول شي، لکه د ملاتړ شاته دفتر، نو دا ځواب راځي:

```json
{
  "error": {
    "code": "integration_token_not_allowed",
    "message": "Business integration credentials are restricted to API v2 and MCP endpoints."
  }
}
```

## د ناکامۍ ځوابونه

| حالت | کوډ | معنا |
| --- | --- | --- |
| 401 | `integration_credential_required` | ټوکن نشته، یا ټوکن د ادغام ټوکن نه دی |
| 401 | `integration_credential_invalid` | اعتبارنامه بېرته اخیستل شوې، سوداګري غیر فعاله، یا د کاروونکي توپیر |
| 403 | `integration_membership_inactive` | د کارکوونکي ګډون لرې شوی دی |
| 403 | `integration_role_revoked` | کارکوونکی نور اداري یا مدیریتي واک نه لري |
| 403 | `integration_branch_scope_empty` | د څانګې ته محدوده اعتبارنامه نور په ساحه کې هېڅ څانګه نه لري |
| 403 | `api_ability_denied` | وړتیا نشته، یا رول نور اړوند صلاحیت نه ورکوي |
| 403 | `branch_scope_denied` | څانګه د اعتبارنامې له ساحې بهر ده |
| 422 | `branch_required` | څو څانګې په ساحه کې دي او هیڅ یې نه ده نومول شوې |
| 403 | `integration_token_not_allowed` | ټوکن په غیر ادغام لاره کې کارول شوی |

## عملیاتي لارښوونې

- په ټاکلي مهال ویش څرخول وکړئ، او د افشا کېدو د هر شک پر مهال سمدلاسه څرخول وکړئ.
- د هر ادغام لپاره یوه اعتبارنامه وساتئ، او هغه د هغه سیسټم په نوم ونوموئ چې ورته کاروي.
- تر ټولو کوچنۍ د وړتیاوو ټولګه او تر ټولو کوچنۍ د څانګو ټولګه ورکړئ.
- `last_used_at` او د کارونې په کارت کې د غوښتنو پېښې تعقیب کړئ.
- ټوکنونه د پیرودونکي په اړخ کې کوډ ته مه ږدئ؛ ادغامونه له سرور سره سر ته وي.
