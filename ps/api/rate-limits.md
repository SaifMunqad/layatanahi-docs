# د نرخ محدودیتونه او کوټې

پر API v2 او MCP هرې غوښتنې باندې دوه خپلواکې ساتنې پلي کېږي:

1. یو **د فج محدودونکی** لنډمهاله سیلابونه مخکې له هر ډول ډاټابیز کار بندوي.
2. یوه **کوټه** محدودوي چې یو کاروونکی په ورځ او په میاشت کې څومره غوښتنې کولای شي.

دواړه `429` د `Retry-After` سرلیک سره راوړي، خو معناوې یې جلا دي او باید په جلا ډول مدیریت شي.

## د فج محدودونکی

| ځانګړتیا | ارزښت |
| --- | --- |
| کړکۍ | 60 ثانیې |
| حد | 60 غوښتنې |
| کیلي | د ادغام اعتبارنامه |
| ترتیب | د څانګې له تصدیق او کوټې دمخه کتل کېږي |

محدودونکی د کوټې د شمېرلونکو څخه دمخه کتل کېږي، نو یو سیلاب د کوټې قطارونه بندولا نشي او کارونه
په غلط ډول لوړولا نشي. له هغه څخه تېرېدل `api_burst_limit_exceeded` او د بیا هڅې لنډ انتظار رامنځته کوي.

## کوټه

| ځانګړتیا | ارزښت |
| --- | --- |
| ساحه | پر کاروونکي، د هغه د ټولو اعتبارنامو ترمنځ شریکه |
| د ورځې اساس | 200 غوښتنې |
| د میاشتې اساس | 2,000 غوښتنې |
| بیا پیل | د ورځې پیل او د میاشتې پیل د سوداګرۍ د وخت سیمې (timezone) سره |

کوټه په هره غوښتنه یو ځل اخیستل کېږي، وروسته له فج کتنې او وروسته له څانګې تصدیق، او د
`/api/v2/context` غوښتنه هم رانغاړي. `/api/v2/health` پرې نه اخیستل کېږي.

## د پلان ضریبونه

| پلان | ضریب | په ورځ کې | په میاشت کې |
| --- | --- | --- | --- |
| Free | 1× | 200 | 2,000 |
| Growth | 3× | 600 | 6,000 |
| Scale | 10× | 2,000 | 20,000 |
| Enterprise | 50× | 10,000 | 100,000 |

پلان د وخت محدود دی. کله چې پای ته ورسیږي، اغېزمن پلان په اتوماتیک ډول Free ته راګرځي، نو هغه
ادغام چې په Growth حدودو یې تکیه کړې وه، بېرته `429` ترلاسه کول پیل کوي.

## د نرخ محدودیت ځوابونه

### فج

```json
{
  "error": {
    "code": "api_burst_limit_exceeded",
    "message": "Too many API requests in a short period.",
    "retry_after_seconds": 17
  }
}
```

### کوټه

```json
{
  "error": {
    "code": "api_quota_exceeded",
    "message": "The API request quota has been reached.",
    "scope": "user",
    "period": "day",
    "limit": 200,
    "used": 200,
    "reset_at": "2026-11-01T00:00:00+04:30",
    "retry_after_seconds": 18234
  }
}
```

دواړه `Retry-After` د ثانیو د صحیح عدد په توګه لري. د ثابت ځنډ پر ځای ورته کار واخلئ.

## د کارونې څارنه

`GET /api/v2/context` اغېزمن پلان، ضریب، د وخت سیمه او اوسنی کارول راوړي:

| فیلډ | معنا |
| --- | --- |
| `quota.plan` | د پای ته رسیدو د قواعدو وروسته اغېزمن پلان |
| `quota.multiplier` | هغه ضریب چې پر اساسي حدودو پلي کېږي |
| `quota.user.day` | د نن لپاره کارول شوی، حد، پاتې او د بیا پیل وخت |
| `quota.user.month` | د دې میاشتې لپاره کارول شوی، حد، پاتې او د بیا پیل وخت |

همغه شمېرې د ترتیباتو په ادغامونو کارت کې هم ښکاري.

## د حدونو دننه ډیزاین

| تخنیک | اغېز |
| --- | --- |
| شپنۍ همغږي د `per_page=100` سره | د هر ریکارډ لپاره کمې غوښتنې |
| د نېټو کړکۍ وکاروئ | کوچني او بیا پیلېدونکي پایلې سیټونه |
| چاپېریال کاش کړئ | په ساعت کې یوه غوښتنه، د هرې غوښتنې پر ځای |
| د محصولاتو ډاټا کاش کړئ | محصولات او ذخیره د پلورونو په پرتله کم بدلیږي |
| په `429` کې ودرېږئ | پاتې کوټه بی‌ځایه مصرفول مخنیوي |
| د هر سیسټم لپاره یوه اعتبارنامه | کارونه د یوه ځانګړي سیسټم پورې نسبت کېدای شي |

کوټه پر غوښتنه اخیستل کېږي، نه پر کرښه، نو یوه لویه پاڼه تل د ډېرو کوچنیو پاڼو په پرتله ارزانه ده.

## څه شی نه شمېرل کېږي

- `/api/v2/health`.
- هغه غوښتنې چې د فج محدودونکي له خوا د کوټې له اخیستلو دمخه ردېږي.
- هغه غوښتنې چې د څانګې د ساحې تېروتنې له امله ردېږي: تصدیق د کوټې له اخیستلو دمخه کېږي او غوښتنه
  `scope_denied` ثبتېږي.
- په ویب انټرفېس کې د کارکوونکو کارونه.

## عملیاتي یادښتونه

- رد شوې غوښتنې لا هم د تفتیش لپاره د غوښتنو په پېښو ثبت کې لیکل کېږي، پرته له دې چې کوټه زیاته کړي.
- `last_used_at` په بریالي تصدیق هویت تازه کېږي، نه په هره غوښتنه.
- د پلان بدلون په راتلونکې غوښتنه پلي کېږي؛ په ټوکن کې کاش شوی استحقاق نشته.
- که دوه ادغامونه یو مالک شریک وي، کوټه هم شریکوي. که جلاوالی غواړئ، مالکان جلا کړئ.
