# ویب‌هوکونه او پېښې

د سوداګرۍ API تر اوسه د بهرنيو ویب‌هوکونو د ترتیبلو امکانات نه لري. د یوه callback URL د ثبت لپاره
هېڅ ننوتنه نشته، د امضا لپاره هېڅ پټ کلید (signing secret) نشته، او د ګډونوالو لپاره د بیا لېږلو قطار هم نشته.

دا پاڼه هغه د پېښو سطحې تشریح کوي چې اوس شتون لري، ترڅو ادغام د ویب‌هوک د رارسېدو د
انتظار پر ځای یوه باوري نمونه وټاکي.

## اوس مهال څه شی شتون لري

| سطحه | لوری | څوک یې کارولای شي |
| --- | --- | --- |
| د تادیې ګیټ‌وی بېرته‌راګرځېدنې (callbacks) | له ورکوونکي څخه اپلیکېشن ته | یوازې د تادیې ورکوونکی |
| د خپرولو چلنلونه (broadcast channels) | له اپلیکېشن څخه براوزر ته | ننوتلي کارکوونکي |
| د خبرتیاوو فید | له اپلیکېشن څخه براوزر ته | ننوتلي کارکوونکي |
| د API v2 پوښل (polling) | له اپلیکېشن څخه پیرودونکي ته | د ادغام اعتبارنامې |

## د تادیې ګیټ‌وی بېرته‌راګرځېدنې

د HesabPay ادغام د تادیې د غونډې د جوړولو او د تادیې د تایید لپاره له سرور څخه تر سرور پورې ننوتنې
ړاندې کوي. دا د اپلیکېشن یا د ورکوونکي له خوا غوښتل کېږي، نه د درېیمو اړخونو د ګډونوالو له خوا:

| ننوتنه | موخه |
| --- | --- |
| `POST /api/v1/hesabpay/create-session` | کوربه (hosted) د تادیې غونډه پیل کړئ |
| `POST /api/v1/hesabpay/verify-payment` | ترسره شوې تادیه تایید کړئ |

ورکوونکی پیرودونکی د چیک‌آوت وروسته د اپلیکېشن بریالیتوب یا ناکامۍ URL ته بېرته لېږي. هغه لېږدونه د
کاروونکي په اړخ دي، ویب‌هوکونه نه دي، او د تادیې د ثبوت په توګه یې مه وګورئ؛ تایید کول اصلي ګام دی.

دې ننوتنو ته Sanctum تصدیق هویت اړین دی او د v2 د ادغام سطحې برخه نه دي.

## د خپرولو چلنلونه

Laravel Reverb د خبرتیاوو او د چټ د سټریمینګ لپاره واقعي وخت پېښې براوزر ته خپروي. چلنلونه په
`routes/channels.php` کې د هر کاروونکي او هرې سوداګرۍ لپاره جلا اجازت لري.

بهرني سیسټمونه نشي کولی د ادغام ټوکن سره دې چلنلونو ونښلي. دا شتون لري چې ویب انټرفېس ژوندی وساتي،
نه دا چې ERP ته ډاټا ورکړي.

## د خبرتیاوو فید

اپلیکېشن د ننوتلي کارکوونکي لپاره د خبرتیاوو فید پوښي (poll کوي). ننوتنې د
`/api/v1/business/notifications` لاندې دي او د براوزر په غونډې تکیه کوي، نو د سرور څخه تر سرور پورې
ادغام ورته نشي کارولای.

که وغواړئ چې د انټرفېس بهر د سوداګرۍ پېښو ته غبرګون وښیئ، نو د سوداګرۍ سرچینې پوښئ (poll کړئ).

## سپارښتنه شوې د ادغام نمونه

ترڅو د بهرنيو ویب‌هوکونو امکانات نه وي راغلي، **د واټرمارک سره پوښل (polling)** وکاروئ:

1. د هرې سرچینې لپاره نوی `created_at` او `id` چې پروسسه مو کړی وي وساتئ.
2. `/api/v2/sales?from=<watermark date>` د `per_page=100` سره وغواړئ.
3. هغه کرښې چې دمخه مو لري پرېږدئ، نورې پروسس کړئ.
4. واټرمارک مخکې انتقال کړئ.
5. په داسې مهال ویش سره تکرار کړئ چې کوټې ته مو مناسب وي: د بېلګې په توګه فرمایشونه په پنځو
   دقیقو، او پلورونه په ساعت کې.

| سرچینه | سپارښتنه شوی مهال ویش | دلیل |
| --- | --- | --- |
| فرمایشونه | 5 دقیقې | د حالت بدلونونه د وخت پورې اړمن دي |
| پلورونه | 15–60 دقیقې | راپور ورکول او پرتله‌کول |
| پېرودونه | په ساعت کې | د عرضه‌کوونکو سندونه ورو بدلیږي |
| ذخیره | 15–60 دقیقې | د نورو چینلونو لپاره د شتون ښکارېدنه |
| محصولات | په ورځ کې | د کټالوګ بدلونونه لږ وي |

کله چې مهال ویش ټاکئ، کوټې ته درناوی وکړئ. د پنځو دقیقو پوښل په هر ننوتنه کې په ورځ کې 288 غوښتنې کوي.

## د راتلونکي ویب‌هوک لپاره ډیزاین

که راتلونکي وختونه بهرني ویب‌هوکونه اضافه شي، ستاسو د ادغام خوندي ډیزاین دمخه چمتو دی که تر اوسه:

- د سرچینې `id` خپله اصلي بهرني کیلي ساتي؛
- `created_at` ساتي او د واټرمارک په توګه یې کاروي؛
- خپل پروسس idempotent ساتي؛
- د دوه ګوني لېږد تحمل کوي؛
- د هر راتلونکي د امضا سرلیک تاییدوي، ترڅو payload ته باور وکړي.

Idempotency تر ټولو مهم دی: ویب‌هوک کیدای شي له یو څخه زیات ولېږل شي، او همدارنګه یوه پوښتل شوې پاڼه.

## څه شی نه وړاندې کېږي

- د subscriber د ثبت هېڅ ننوتنه.
- د پېښو ډولونه یا د payload کټالوګ نشته.
- د لېږد لاګونه یا بیا خپرول (replay) نشته.
- د بهرنيو پېښو لپاره HMAC امضا نشته.
- د ادغامونو لپاره د websocket فید نشته.

د جبران لپاره ویب انټرفېس مه سکریپ (scrape) کوئ. هغه د غونډې پر بنسټ دی، پرته له خبرتیا بدلیږي او د API د
یوازې-لوستلو هوکړې سره مخامخ دی.
