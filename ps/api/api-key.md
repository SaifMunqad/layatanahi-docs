# API کلیدونه او صلاحیتونه

د API اعتبارنامې د سوداګرۍ د ترتیباتو له پردې څخه جوړېږي، نه د جلا پراختیالیکار دروازې څخه. دا
مالکیت روښانه ساتي: یوه اعتبارنامه د یوه کارکوونکي پورې اړه لري، د هغه کارکوونکي واک په میراث
بولي، او کله چې کارکوونکی شرکت پرېږدي له خدمته ورک کېږي.

د هغوی د مدیریت لپاره **ترتیبات > API ادغامونه** پرانیستئ.

## څوک کولی شي اعتبارنامه جوړه کړي

| رول | کتلای شي | جوړولای شي | مدیریت کولای شي |
| --- | --- | --- | --- |
| د سوداګرۍ مدیر | د سوداګرۍ ټولې اعتبارنامې | هو | د سوداګرۍ هره اعتبارنامه |
| د څانګې مدیر | یوازې خپلې اعتبارنامې، په مدیریت شوو څانګو محدودې | هو | یوازې خپلې |
| نور کارکوونکي | نه | نه | نه |

مدیریت پدې معنی دی: نوم بدلون، څرخول او بېرته اخیستل. جوړول او مدیریت د `settings` د لیکلو
وړتیا غواړي.

## د اعتبارنامې جوړول

1. **ترتیبات > API ادغامونه** پرانیزئ.
2. **جوړول** وټاکئ.
3. داسې نوم ولیکئ چې مصرفوونکی سیسټم وپېژني، د بېلګې په توګه `ERP sync` یا `Claude Desktop`.
4. لږ تر لږه یوه وړتیا وټاکئ.
5. پریکړه وکړئ چې اعتبارنامه د ټولې سوداګرۍ ده یا څانګو ته محدوده.
6. خوندي کړئ، بیا سمدلاسه پټ کوډ کاپي کړئ.

| ساحه | اړینه | قواعد |
| --- | --- | --- |
| نوم | هو | تر 120 تورو پورې |
| وړتیاوې | هو | لږ تر لږه یوه له پنځو ملاتړ شوو وړتیاوو |
| د ټولې سوداګرۍ | هو | بولین (Boolean) |
| د څانګو پېژندونکي | کله چې د ټولې سوداګرۍ نه وي | لږ تر لږه یو، عددونه، بې‌ساره |

پټ کوډ یوازې یو ځل ښودل کېږي. یوازې هاش ذخیره کېږي، نو وروسته بېرته نه لاسته راځي؛ که ورک شي،
اعتبارنامه څرخوئ.

## وړتیاوې

| وړتیا | څه شی خلاصوي | همدا راز اړین |
| --- | --- | --- |
| `products:read` | د محصولاتو کټالوګ او لټون | `inventory.products.read` |
| `stock:read` | د هرې څانګې د ذخیرې کرښې | `inventory.branches.read` |
| `purchases:read` | د پېرود لیست او تفصیل | `purchase.purchases.read` |
| `orders:read` | د فرمایشونو لیست | `sale.orders.read` |
| `sales:read` | د پلور لیست او تفصیل | `sale.sales.read` |

د لیکلو هېڅ وړتیا نشته. د یوهې وړتیا ورکول هېڅکله هغه څه نه زیاتوي چې کارکوونکی یې په انټرفېس کې
کولای شي، او د یوه رول څخه د پاڼې صلاحیت لرې کول اړوندې وړتیا په چوپ‌تړالې سره بندوي.

## د ټولې سوداګرۍ او د ټاکلو څانګو توپیر

| حالت | چلند | معمول کارونه |
| --- | --- | --- |
| د ټولې سوداګرۍ | ټولې فعالې څانګې لولي، ترڅو چې یوه څانګه ونومول شي | مرکزي راپور ورکول، د ERP همغږي |
| ټاکلې څانګې | یوازې ورکړل شوې څانګې لولي؛ یوه څانګه په اتوماتیک ډول ټاکل کېږي | د سیمه‌ییز ګودام وسیله |

د څانګې مدیر نشي کولی داسې د ټولې سوداګرۍ اعتبارنامه جوړه کړي چې هغه څانګې ته هم ورسیږي چې هغه یې
مدیریت نه کوي. سرور ورکړل شوې څانګې د مدیر له ژوندۍ ساحې سره پرتله کوي او له حد زیاته غوښتنه ردوي.

## څرخول او بېرته اخیستل

| عمل | اغېز |
| --- | --- |
| نوم بدلون | یوازې لیبل بدلوي؛ ټوکن کار ته دوام ورکوي |
| څرخول | نوی پټ کوډ او نوی ټوکن صادروي؛ پخوانی ټوکن سمدلاسه کار بندوي |
| بېرته اخیستل | اعتبارنامه د "بېرته اخیستل شوې" په توګه نښه کوي؛ هره غوښتنه په `401` کې ناکامېږي، تل |

بېرته اخیستل شوې اعتبارنامې نه شي څرخېدای، نوم یې نه شي بدلېدای او نه بیا فعالېدای شي. پر ځای یې نوې
اعتبارنامه جوړه کړئ.

څرخول د افشا کېدو د شک په وړاندې سم ځواب دی، ځکه زوړ پټ کوډ له منځه وړي او د اعتبارنامې تاریخچه
نه له منځه وړي.

## د کارونې کارت لوستل

د ادغامونو ټب پلان، ضریب، د ورځې او میاشتې اجازه، اوسنی کارول او د بیا پیل وخت ښیي، او همدارنګه د
هرې اعتبارنامې د وروستیو غوښتنو پایلې.

| ساحه | معنا |
| --- | --- |
| پلان | اغېزمن پلان: free، growth، scale یا enterprise |
| ضریب | په اساسي اجازه باندې پلي کېږي |
| Used / limit | په اوسنۍ موده کې مصرف شوې غوښتنې |
| Reset at | هغه وخت چې د مودې پوله ته رسیږي |
| Last used | د اعتبارنامې وروستۍ بریالۍ تصدیق هویت |

کوټه د کاروونکي پر مخ ده، نه د اعتبارنامې پر مخ: هغه څو اعتبارنامې چې یو کارکوونکي لري، یوه ګډ
ټوک کاروي.

## د خوندیتوب چک‌لیست

- د هر مصرفوونکي سیسټم لپاره یوه اعتبارنامه، په روښانه توګه نومول شوې.
- لږې وړتیاوې او لږې څانګې.
- پټ کوډ د پټو کلیدونو په مدیر کې وساتئ، هېڅکله د سرچینې په مدیریت (source control) کې مه ږدئ.
- د کارکوونکو له بدلون یا د افشا کېدو وروسته څرخول.
- هغه اعتبارنامه چې کارونه پکې نه کېږي، فعال مه پریږدئ؛ بېرته یې واخلي.
- `last_used_at` وګورئ؛ چوپ‌تړه اعتبارنامه معمولاً هېر شوی ادغام دی.
