# د پېرود لنډه کتنه

د پېرود ماژول هغه هر څه ثبتوي چې سوداګري **دننه** راوړي: له عرضه کوونکو پیرودل شوي توکي، له بلې
څانګې څخه ترلاسه شوې ذخیره، د عرضه کوونکو ارډرونه، هغه بلونه چې تاسو ورته پوروړي یاست، او هغه
بېرته راستنونې چې تاسو یې لېږئ. دا د پلور ماژول سیاله برخه ده او ستاسو څانګې ته د زخیرې د ننوتلو
اصلي سرچینه ده.

پېرودونه مالي سندونه دي، نه یوازې د زخیرې حرکتونه. هر پېرود یو بل، د څانګې پر حساب یوه تادیه، د
ترلاسه کوونکي ګودام لپاره د زخیرې کرښې او د فعالیت یو تعقیب جوړوي. همدا لامل دی چې دا ماژول د
څو پاڼو په واسطه ساتل کېږي، هره یوه د خپل لوستلو او لیکلو کچې سره.

## د پېرود ژوند بهیر

یو پېرود معمولاً دې پړاوونو څخه تېرېږي:

1. **ارډر** — تاسو د عرضه کوونکي یا بلې څانګې لپاره د پېرود ارډر چمتو کوئ. لا هېڅ شی نه ځي.
2. **ترلاسه کول** — ارډر پېرود ته اوړي؛ ذخیره ترلاسه کوونکي ګودام ته ورزیاتېږي.
3. **بل** — بل ثبتوي چې څومره پوروړی یاست او څومره تادیه شوې ده.
4. **تادیه** — پیسې له څانګې حساب څخه وځي، جزوي یا بشپړ.
5. **بېرته راستنونه** — زیانمن یا ناسم توکي بېرته ځي، د پیسو د بېرته راګرځېدو یا د کم شوي بل سره.

هر پېرود ارډر ته اړتیا نه لري. ډېرې څانګې پېرود مستقیم هغه وخت ثبتوي چې توکي رارسيږي، او بل
وروسته د ریکارډونو پاڼې څخه تصفیه کوي.

## د دې ماژول پاڼې

| پاڼه | موخه | واک |
| --- | --- | --- |
| پېرودونه | د څانګې د پېرود بلونو ثبت | `purchase.purchases` |
| پېرود کول | پېرود ثبت او تادیه کول | `purchase.purchases` write |
| د پېرود کتل | د تادیو او بېرته راستنونو سره د چاپ وړ بل | `purchase.purchases` |
| عرضه کوونکي | د سوداګرۍ د عرضه کوونکو لارښود | `purchase.suppliers` |
| د پېرود ارډرونه | عرضه کوونکو یا څانګو ته لېږل شوي ارډرونه | `purchase.orders` |
| د پېرود غوښتنې | له نورو څانګو غوښتنې چې ستاسو پرېکړې ته انتظار دي | `purchase.requests` |
| ریکارډونه | بلونه، تادیې او ټولګې | `purchase.records` |
| بېرته راستنونې | عرضه کوونکو ته بېرته راستن شوي توکي | `purchase.returns` |

## هغه حالتونه چې به یې وینئ

پېرودونه د پلور سره د سوداګرۍ یوه ګډه ټولګه شریکوي:

| ارزښت | مانا |
| --- | --- |
| مسوده (Draft) | جوړ شوی خو لا تایید شوی نه دی |
| د تایید په تمه (Pending approval) | د ترلاسه کوونکي لوري د منلو انتظار |
| تایید شوی (Approved) | منل شوی، ذخیره ممکن لا ترلاسه شوې نه وي |
| ارډر شوی (Ordered) | عرضه کوونکي ته لېږل شوی |
| ترلاسه شوی (Received) | په بشپړه توګه ترلاسه شوی |
| جزوي ترلاسه شوی (Partially received) | ځینې کرښې رسېدلې دي |
| لغوه شوی (Cancelled) | د بشپړېدو دمخه پرېښودل شوی |
| بېرته راستن شوی (Returned) | په بشپړه توګه بېرته راستن شوی |
| تادیه په تمه (Payment pending) | توکي ترلاسه شوي، پیسې لا پورې دي |
| بشپړ شوی (Completed) | ترلاسه او تادیه شوی |
| په ذخیره کې (In stock) | ذخیره شوی او شته |

بلونه خپل جلا د تادیې حالت لري: نه تادیه شوی، جزوي تادیه شوی یا تادیه شوی. یو پېرود کولی شي
*ترلاسه شوی* وي خو بل یې لا *نه تادیه شوی* وي؛ دواړه حقایق مهم دي او دواړه پر سکرین ښکاري.

## څه شی محدود دي

- ټول د پېرود لیستونه د څانګې ساحې لري. یوازې هغه بلونه، ارډرونه، تادیې او بېرته راستنونې وینئ
  چې د ستاسو په غونډه کې ټاکل شوې څانګې صادري یا هغې ته استول شوې وي.
- سمون او ړنګول د هر ریکارډ لپاره د دوو نښو په واسطه کنټرولېږي: **د سمون وړ** او **د ړنګولو
  وړ**. کله چې یو همکار له پېرود کتنې څخه یوه نښه لرې کړي، اړوند عمل له لیست څخه ورکېږي او د
  سمون URL له پرانیستلو ډډه کوي.
- تادیه غواړي چې بل ستاسو څانګې ته اړ وي او حساب په هماغې اسعارو کې فعال څانګیز حساب وي.
- بېرته راستنونې نشي کولی له پیرودل شوي څخه زیاتې وي، او نه له هغه مقدار څخه چې لا لاس کې دی.
- عرضه کوونکي د ټولې سوداګرۍ دي، نو په یوه څانګه کې جوړ شوی عرضه کوونکی په ټولو څانګو کې
  ښکاري. د پېرود سندونه داسې نه دي.
- اندازې، د حساب بیلانسونه او ذخیره د ډاټابیس د یوې معاملې دننه تازه کېږي. ناکامه تادیه یا د
  زخیرې تازه کول ټوله عملیه بېرته ګرځوي.

## سپارښتل شوی کاري بهیر

1. له **پېرود > عرضه کوونکي** څخه عرضه کوونکي جوړ یا وارد کړئ.
2. له **پېرود کول** څخه پېرود ثبت کړئ، ترلاسه کوونکی ګودام او تادیه کوونکی حساب وټاکئ.
3. کله چې عرضه کوونکی وروسته تادیه شي، بل له **ریکارډونه > بلونه** څخه پرانیزئ.
4. کله چې توکي بېرته راشي **بېرته راستنونې** وکاروئ او اجازه ورکړئ سیسټم ذخیره او بل سم کړي.
5. کله چې کاغذي کار بشپړ شو، د سمون وړ نښه لرې کړئ ترڅو سند قلف شي.
