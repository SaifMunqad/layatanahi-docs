# د ماليې لنډه کتنه

مالیه هغه ځای دی چې پیسې پکې حساب کېږي. هر پلور، پېرود، معاش، د مالیې تادیه او عملیاتي لګښت په
پای کې د څانګې یو حساب ته رسېږي، او دا ماژول هغه څرنګوالی دی چې تاسو پرې دا حرکتونه ګورئ، ثبتوئ
او سره سمون ورکوئ.

ماژول د څانګې په کچه محدود دی: هره څانګه خپل حسابونه، عواید، لګښتونه، مالیې او معاشونه ساتي.
شریکان او وېشنې د سوداګرۍ په کچه شریکې دي، ځکه چې دوی شرکت توصیفوي نه یو ځانګړی ځای.

## دا پاڼه د څه په اړه ده

- په نوملړ شوو حسابونو کې پیسې ساتل او د هر بیلانس پېژندل.
- هغه عواید ثبتول چې پلور نه دي او هغه لګښتونه ثبتول چې پېرود نه دي.
- کارکوونکو ته معاش ورکول، په شمول د فیصدۍ پر بنسټ معاش.
- مالیې سمبالول او د مالیې راپورونه جوړول.
- د سوداګرۍ د ملکیت ونډې بیا کتل.

## په دې ماژول کې پاڼې

| پاڼه | موخه | واک |
| --- | --- | --- |
| حسابونه | نغدي، بانکي، والټ او کارت بیلانسونه | `finance.accounts` |
| د تادیې غوښتنې | د څانګو ترمنځ د پیسو لېږد چې د تایید په تمه دی | `finance.accounts` |
| عواید | غیر پلوري عواید د وېشنو سره | `finance.incomes` |
| لګښتونه | عملیاتي لګښتونه، په اختیاري ډول د عرضه کوونکي بل سره | `finance.expenses` |
| مالیې | د مالیې وېشنې، تادیې او راپورونه | `finance.taxes` |
| معاشونه | ټاکل، پټې، انعامونه او کموالی | `finance.salaries` |
| شریکان | د سوداګرۍ د ملکیت ونډې | `finance.partners` |

## حساب د ماژول مرکز دی

هر مالي امر په پای کې د حساب بیلانس ته یو بدلون دی:

| پېښه | پر حساب اغېزه |
| --- | --- |
| اوس تادیه شوی پلور | کریډیټ (بیلانس زیاتېږي) |
| وروسته راټول شوی پلور | کریډیټ |
| تادیه شوی پېرود | ډیبټ |
| ثبت شوی عاید | کریډیټ |
| ثبت شوی لګښت | ډیبټ |
| تادیه شوی معاش | ډیبټ |
| تادیه شوې مالیه | ډیبټ |
| تایید شوې د لېږد غوښتنه | لېږونکی ډیبټ، ترلاسه کوونکی کریډیټ |
| د سرمایه سمون | ډیبټ یا کریډیټ، د نښې له مخې |

حسابونه هېڅکله نه ړنګېږي. د یو حساب کارول بندولو لپاره یې غیر فعال په نښه کړئ؛ تاریخچه سمه پاتې
کېږي.

## د اسعارو سمبالول

هر حساب یوازې یو اسعار لري. په بل اسعار کې تادیه باید د تبادلې اندازه ولري، چې سیستم ترې نرخ
اخیستي او بنسټیزه اندازه ذخیره کوي. راپورونه بنسټیزه اندازه کاروي، نو ټولګې په بېلابېلو اسعارو کې هم
د پرتله وړ پاتې کېږي.

که د حسابونو ښکته لیست تش ښکاره شي، معمولاً مانا دا ده چې په سند کې د هماغه اسعارو فعال حساب
نیشته، نه دا چې پاڼه خرابه ده.

## څه شی محدود دي

- لوستل د پاڼې واک غواړي؛ هر مالي بدلون write غواړي. په مالي پاڼه کې write پراخ دی: په هماغه پاڼه
  کې جوړول، سمون، تادیه او ړنګول رانغاړي.
- ټول لیستونه او بیلانسونه د غونډې له لارې د څانګې په کچه محدود دي. د بلې څانګې حسابونه او سندونه
  د لاسرسي وړ نه دي.
- هغه مالي سندونه چې دمخه یې تادیه جوړه کړې ساتل کېږي: سمون لومړی پخوانۍ تادیه بېرته ګرځوي، او
  ړنګول هغه ځای بندېږي چې بیلانس پکې ناسم یا له نظمه وتلی شي.
- حسابونه، د عوایدو داخلې او د لګښتونو داخلې هېڅکله کلک نه ړنګېږي. سیستم بېرته ګرځوي او په نرمه
  توګه ړنګوي ترڅو د تفتیش لړ پاتې شي.
- د مالیې او معاش پاڼې ځینې GET سکرینونه د write عملونو په توګه ګڼي، ځکه چې پرانیستل یې د تادیې
  بهیر پیلوي.
- یوازې د سوداګرۍ کچې رولونه او د حسابدارۍ څانګه په ډیفالټ ډول مالي واکونه ترلاسه کوي.

## د تنظیم سپارښتل شوی ترتیب

1. ستاسو څانګه چې کوم اسعار کاروي، د هر یوه لپاره لږ تر لږه یو حساب جوړ کړئ.
2. د داخلونو ثبتولو دمخه د عوایدو او لګښتونو وېشنې جوړې کړئ.
3. هغه د مالیې وېشنې تایید کړئ چې سوداګري باید پرې راپور ورکړي.
4. کارکوونکو ته معاشونه وټاکئ او د هر ټاکل شوي معاش اسعار وګورئ.
5. حسابونه هره ورځ وګورئ، او په اونۍ ډول له نغدي او بانکي صورتونو سره سمون ورکړئ.
