# د لاسرسي د تفتیش ثبت

پر هر رول یا هرې ورکړې هر بدلون ثبتېږي. د تفتیش ثبت دا تاریخچه په ساده ژبه ښیي: چا څه
بدل کړل، کله، او په دقیق ډول کومې وړتیاوې زیاتې یا لرې شوې. دا د "چا دا کس ته ماليې ته لاسرسی
ورکړ؟" پوښتنې ځواب دی.

ثبت یوازې زیاتېدونکی دی. پر دې پاڼه د سمون، ړنګولو یا صادرولو هېڅ عمل نشته.

## دا پاڼه د څه په اړه ده

- ثابتول چې د اجازو بدلونونه اجازه شوي او تعقیبېدونکي وو.
- د رول د سمون اغېزې کتنه پرته له دې چې پخپله رول پرانیزئ.
- د امنیتي کتنې وروسته د ناڅاپي لاسرسي پلټنه.

## د پاڼې جوړښت

| ستون | څه شی ښیي |
| --- | --- |
| عمل | رنګین ټوټه د عمل کوډ سره، د بېلګې په توګه رول جوړ شو یا ورکړه بېرته واخیستل شوه |
| بیاکتنه | هغه بیاکتنې شمېره چې بدلون تولید کړه |
| بدلونونه | پر هر عملیات یو کارت، د زیاتو، لرې شوو او ټولو وړتیاوو شمېرو سره |
| ترسره کوونکی | هغه کارکوونکی چې بدلون یې ترسره کړ |
| نېټه | کله چې بدلون وشو، ستاسو د کلیزې غوره توب له مخې |

لیست په یوه وخت کې پنځه ویشت کرښې باروي او لکه څنګه چې سکرول کوئ دوام ورکوي. د بدلون کارت
پراخول بشپړ د وړتیاوو توپیر او، کله چې اړوند وي، اړوند رول یا کارکوونکی ښیي.

## څنګه یې کارول

1. **پلورنځی > کارکوونکي > تفتیش** پرانیزئ.
2. د عمل ټوټې وګورئ: شنې رنگې جوړول او ورکړې ښیي، سرې رنگې ړنګول، بېرته اخیستل او وتل
   پوښي، بېرنګه نور ساتنه رانغاړي.
3. هغه ننوتنه ومومئ چې ورته اړتیا لرئ او پراخه یې کړئ.
4. توپیر ولولئ: زیاتې شوې وړتیاوې، لرې شوې وړتیاوې او پایله کې ټولګه.
5. له عمل کولو دمخه د رول پاڼه یا د کارکوونکي د لاسرسي پاڼه سره یې پرتله کړئ.

## د عملونو مرجع

| عمل | معنا |
| --- | --- |
| رول جوړ شو | نوی رول تعریف شو |
| رول تازه شو | نوم، ساحه یا وړتیاوې بدلې شوې |
| رول ړنګ شو | رول لرې شو او ورکړې پای ته ورسېدې |
| ورکړه وشوه | یو کارکوونکي رول ترلاسه کړ |
| ورکړه بېرته واخیستل شوه | رول له یوه کارکوونکي واخیستل شو |
| ورکړې همغږې شوې | د کارکوونکي رولونه په یوه عملیات کې سره برابر شول |
| کارکوونکی ووت | کارکوونکی ووت او رولونه یې بند شول |
| د څانګې مدیر وټاکل شو | یوې څانګې ته مدیر وټاکل شو |
| مدیر برابر شو | لومړنی مدیر جوړ شو |
| مدیر رغاوه شو | نیمګړې د مدیر ورکړه بیا ورغول شوه |
| سیسټمي رولونه ولول شول/ولیکل شول | د سیسټمي رولونو تعریفونه پلي شول |
| سیسټمي رولونه بیا جوړ شول | سیسټمي رولونه نوي کاتالوګ ته سم شول |
| دیپارټمنټ بشپړ شو | شته کارکوونکو د دیپارټمنټ ډیفالټونه ترلاسه کړل |
| د یوځای کېدو رولونه | کله چې کارکوونکی یوځای شو، رولونه پلي شول |

هره ننوتنه د بیاکتنې شمېره هم ښیي. بیاکتنې په یوې خوا زیاتېږي، چې تاسو ته اجازه ورکوي تایید
کړئ چې د اجازو تر ټولو نوی نسخه ګورئ.

## څه شی محدود دي

- کتل `access.audit` لوستنې وړتیا غواړي. لیکنې وړتیا نشته او هېڅ پای ټکی ثبت نه بدلوي.
- لکه ټولې `access.*` پاڼې، دا یوازې د سوداګرۍ ساحې د ادارې رولونو ته محدوده ده. د څانګې
  مدیران، د مدیریت قالب په ګډون، نه شي پرانیستلای.
- ننوتنې ستاسو سوداګرۍ ته محدودې دي. د رول او کارکوونکي نومونه یوازې د ننوتلې سوداګرۍ ریکارډونو
  لپاره موندل کېږي.
- پاڼه هېڅکله پټنومونه، ټوکنونه یا شخصي ډاټا نه ښیي، پرته له هغه کارکوونکي نوم چې بدلون ته
  نښلول شوی دی.
- د کارکوونکي له اخراج وروسته هم ننوتنې پاتې کېږي، نو لړلیک له کارمند بدلون څخه ژوندی پاتې
  کېږي.

## لارښوونې او د ستونزو حل

- **د وړتیا یو بدلون نشته.** تایید کړئ چې سمه سوداګري ګورئ او بدلون د بلې څانګې د رولونو په
  ټولګه کې نه دی شوی. دلته یوازې د لاسرسي اداره ثبتېږي؛ عملیاتي بدلونونه د پلورنځي په
  فعالیتونو کې ښکاري.
- **ترسره کوونکی د سیسټم عمل ښکاري.** د برابرولو او ډکولو کارونه پرته له انساني ترسره کوونکي
  ځي؛ دا ننوتنې د پلیټفارم له لوړولو یا لومړني ترتیباتو وروسته نورمالې دي.
- **نومونه خالي دي.** اړوند رول یا کارکوونکی کېدای شي له بدلون وروسته ړنګ شوی وي. توپیر او
  بیاکتنه لا هم سم دي.
- **د پلټونکي لپاره صادرول ته اړتیا لرئ.** سکرین شاټ واخلئ یا جدول کاپي کړئ؛ محصول د دې ثبت
  د CSV صادرول نه برابروي.
