# د پلور لنډه کتنه

د پلور ماژول هغه هر څه ثبتوي چې له سوداګرۍ وځي: د کاونټر پلور، نورو څانګو ته پلور، د پیرودونکو
فرمایشونه، بلونه، رسیدونه او بېرته راستنونې. دا د پېرود سیال او د عاید، د زخیرې کموالي او د
پیرودونکو د بیلانسونو اصلي سرچینه ده.

هر پلور یوه مالي پېښه ده. د یوه ثبتول بل، تادیه (کله چې تادیه شي)، په پلورونکي ځای کې د زخیرې
حرکتونه، د پیرودونکي د بیلانس بدلون او د فعالیت تعقیب جوړوي. همدا لامل دی چې ماژول څو پاڼې لري،
هره یوه د خپل واک سره.

## د پلور ژوند بهیر

1. **پلور** — توکي، ترلاسه کوونکی، بیه او حساب ثبتوئ.
2. **بل** — سند ټوله ټولګه، تادیه شوې اندازه او پاتې پور ثبتوي.
3. **تادیه** — پیسې سمدلاسه یا وروسته د څانګې حساب ته رارسيږي.
4. **تحویل** — توکي له زخیرې ځای څخه وځي.
5. **بېرته راستنونه** — پیرودونکی توکي بېرته راوړي او بل سمېږي.

بلې څانګې ته پلور بېل بهیر لري: ترلاسه کوونکې څانګه باید پلور ومني ترڅو پېرود شي او ذخیره هلته
وخوځېږي. تر هغه دمخه پلور **د تایید په تمه** پاتې کېږي.

## د دې ماژول پاڼې

| پاڼه | موخه | واک |
| --- | --- | --- |
| پلور | عادي د پلور فورم د کارټ او تادیې سره | `sale.sell` |
| چټک پلور | ژر د کاونټر ننوتنه د ګټې مخکتنې سره | `sale.sell` |
| پلورونه | د څانګې د پلور بلونو ثبت | `sale.sales` |
| د پلور کتل | د چاپ وړ بل د تادیو او بېرته راستنونو سره | `sale.sales` |
| پیرودونکي | د ټولې سوداګرۍ د پیرودونکو لارښود | `sale.customers` |
| د پلور فرمایشونه | له نورو څانګو ترلاسه شوي فرمایشونه | `sale.orders` |
| د پلور غوښتنلیکونه | هغه غوښتنلیکونه چې ستاسو څانګې نورو څانګو ته لېږلي | `sale.requests` |
| ریکارډونه | بلونه، تادیې او ټولګې | `sale.records` |
| بېرته راستنونې | د څانګې پلورنو پر وړاندې بېرته راګرځېدنې | `sale.returns` |

## هغه حالتونه چې به یې وینئ

| ارزښت | مانا |
| --- | --- |
| مسوده | خوندي شوی خو لا تایید شوی نه دی |
| د تایید په تمه | د ترلاسه کوونکې څانګې د منلو انتظار |
| تایید شوی | د ترلاسه کوونکي له خوا منل شوی |
| فرمایش شوی | فرمایش ورکړل شوی |
| ترلاسه شوی | توکي د ترلاسه کوونکي له خوا ترلاسه شوي |
| جزوي ترلاسه شوی | د فرمایش یوه برخه رسېدلې ده |
| لغوه شوی | پرېښودل شوی |
| بېرته راستن شوی | په بشپړه توګه بېرته راستن شوی |
| تادیه په تمه | توکي تحویل شوي، پیسې لا پورې دي |
| بشپړ شوی | تحویل او تادیه شوی |
| په ذخیره کې | په ترلاسه کوونکې ذخیره کې شته |

جلا له دې، هر بل خپل د تادیې حالت لري: نه تادیه شوی، جزوي تادیه شوی یا تادیه شوی. یو پلور کولی شي
بشپړ وي خو بل یې جزوي تادیه شوی وي؛ دواړه حقایق پر سند ښکاري.

## څه شی محدود دي

- هر لیست د هغې څانګې په ساحه کې دی چې پلور یې صادری کړی. د بلې څانګې پلور هېڅکله نه ښکاري،
  حتی د مستقیم لینک په واسطه.
- پلور `sale.sell` write غواړي. عادي او چټک د پلور سکرینونه د لیکلو پاڼو په توګه ګڼل کېږي، حتی
  که د GET غوښتنې سره پرانیستل شي، ځکه پرانیستل یې د مالي عمل پیل دی.
- ترلاسه کوونکی باید سوداګرۍ ته اړ وي او نشي کولی ستاسو خپله څانګه وي. ځان ته پلور رد کېږي.
- د پلور اسعار باید د هر محصول د زخیرې کرښې له اسعارو سره سمون ولري. د ګډو اسعارو کارټونه رد کېږي.
- له مقدار زیات پلور یوازې هغه وخت اجازه لري چې څانګه یې په خپلو تنظیماتو کې په ښکاره توګه فعال
  کړي.
- ذخیره، د حساب بیلانسونه، بلونه او د تادیې غوښتنلیکونه په یوه معامله کې لیکل کېږي؛ ناکامي هر څه
  بېرته ګرځوي.
- ړنګول او سمون د هر ریکارډ لپاره د سمون وړ او د ړنګولو وړ نښو په واسطه کنټرولېږي، په بشپړه توګه
  لکه پېرودونه.

## سپارښتل شوی کاري بهیر

1. تایید کړئ چې د هر هغو اسعارو لپاره چې پکې پلور کوئ، د پیسو ترلاسه کوونکی څانګیز حساب شته.
2. پیرودونکي ورزیات یا وارد کړئ، یا یوې څانګې ته د ترلاسه کوونکي په توګه پلور وکړئ.
3. پلور له **پلور** څخه ثبت کړئ، او کله چې پیرودونکی همدا اوس تادیه کوي زیرمه حساب وټاکئ.
4. وروسته د پاتې بلونو راټولولو لپاره **ریکارډونه** وکاروئ.
5. کله چې توکي بېرته راشي **بېرته راستنونې** وکاروئ، او کله چې سند پایلي شو قلف یې کړئ.
