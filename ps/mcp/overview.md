# د MCP لنډه کتنه

ماډل کنټېکسټ پروتوکول (MCP) مصنوعي ذکا (AI) کلاینت ته — Claude Desktop، Cursor، د IDE اجنټا یا خپل جوړ شوی مرستیال — اجازه ورکوي چې افزارونه (tools) په جوړښتمي ډول پر سرور وبولي. Layatanahi یو یوازې-د-لولستلو MCP سرور وړاندې کوي ترڅو مرستیال ستاسو د سوداګرۍ په اړه پوښتنو ته ځواب ویلای شي، پرته له دې چې له پردې څخه متن راوباسي یا کاپي-پیست وکړي.

سرور دوهم API نه دی. هماغه د سوداګرۍ ډاټا، هماغه د ادغام اعتبارنامه، هماغه وړتیاوې، هماغه د څانګې محدوده او د `/api/v2` سره هماغه کوټه کاروي.

## سرور څه وړاندې کوي

| ځانګړتیا | جزئیات |
| --- | --- |
| افزارونه | توکي، ذخیره، پېرود، ارډرونه، پلور |
| سرچینې | هېڅ |
| پرامپټونه | هېڅ |
| ترانسپورټ | Streamable HTTP |
| لور | یوازې لوستل |
| تصدیق | د سوداګرۍ د ادغام Bearer token |

هر افزار هماغه ډاټا ستنوي لکه د سمون لرونکي HTTP پای ټکی، پشمول د پاژنې (pagination) میټاډاټا. د لیکلو هېڅ افزار شتون نلري، نو مرستیال نه شي کولای پلور جوړ کړي، بیه بدل کړي یا بل ته تادیه وکړي.

## ولې د خام HTTP پر ځای MCP وکاروئ

| اړخ | MCP | خام HTTP |
| --- | --- | --- |
| کشف | کلاینت افزارونه او د هغوی سکیمونه لیست کوي | تاسو اسناد لولئ او غوښتنې جوړوئ |
| آرګومانونه | د هر افزار لپاره JSON سکیم، چې سرور یې تاییدوي | لاسي د پوښتنې پارامترونه |
| د ادغام هڅه | یوازې یو URL او token ترتیب کړئ | یو کلاینت ولیکئ |
| ساتنې | د افزار تشریحات او سکیمونه ماډل محدودوي | ماډل کولی شي هر URL وبولي |

کله چې مصرف‌کوونکی یو LLM وي، MCP غوره انتخاب دی. هغه وخت HTTP وکاروئ چې مصرف‌کوونکی یو ټاکلی (deterministic) پروګرام وي.

## جوړښت

```text
AI client
   │  POST /mcp/business   (JSON-RPC over Streamable HTTP)
   ▼
BusinessApiServer
   ├── products tool  ─┐
   ├── stock tool      │
   ├── purchases tool  ├──► BusinessApiReadService ──► business data
   ├── orders tool     │
   └── sales tool     ─┘
   ▲
   └── credential, live permissions, branch scope, quota
```

د اعتبارنامو پایپ‌لاین له هر افزار له پلي کولو مخکې ترسره کېږي: غړیتوب، وړتیا، د څانګې ټاکل، د burst حد او کوټه ټول کټ مټ هماغه څنګه چې د HTTP غوښتنې لپاره ارزول کېږي، پکې پلي کېږي.

## پنځه افزارونه

| افزار | وړتیا | څه لولي |
| --- | --- | --- |
| `products` | `products:read` | د لټون سره کاتالوګ |
| `stock` | `stock:read` | د هرې څانګې د زیرمې کرښې |
| `purchases` | `purchases:read` | د پېرود لیست او جزئیات |
| `orders` | `orders:read` | د څانګو ترمنځ ارډرونه |
| `sales` | `sales:read` | د پلور لیست او جزئیات |

د افزار نومونه د سرور له ثبت څخه اخیستل کېږي او د `tools/list` له لارې لیستېږي. د سکیمونو او مثالونو لپاره [د MCP افزارونه](/docs/mcp/tools) وګورئ.

## مرستیال څه کولی شي او څه نه شي کولای

| کولی شي | نه شي کولای |
| --- | --- |
| کاتالوګ وپلټي | توکي جوړ کړي یا ورته سمون ورکړي |
| د هرې څانګې زیرمه راپور کړي | زیرمه تنظیمه، لیږد یا یوځای کړي |
| د پېرود، ارډرونو او پلور لنډیز وکړي | اسناد تادیه، بېرته واستوي یا لرې کړي |
| یو سند د کرښو توکو (line items) سره واخلي | حسابونو، معاشاتو یا رولونو ته لاسرسی ونه لري |
| د کاروونکي د څانګې محدوده درناوي کړي | بلې سوداګرۍ ته وتښتي |

## محدوده او خوندیتوب

- سرور هر څه له اعتبارنامې څخه اخلي. د "admin mode" آرګومنت شتون نلري.
- د څانګې محدوده له افزار له پلي کولو مخکې پلي کېږي؛ د افزار بلل نه شي کولای هغه پراخه کړي.
- واکونه په هره غوښتنه کې بیا ارزول کېږي، نو ښکته شوی کارکوونکی سمدلاسه لاسرسی له لاسه ورکوي.
- پایلې یوازې هغې سوداګرۍ ته محدودې دي چې اعتبارنامه یې خاوندانې ده.
- د محلي سنډبکس پای ټکي یوازې په local او testing چاپیریالونو کې د debug له فعالېدو سره شتون لري.

## اړتیاوې

| اړتیا | جزئیات |
| --- | --- |
| سوداګري | فعاله، لږ تر لږه د یوې څانګې سره |
| اعتبارنامه | په ترتیباتو کې د هغو وړتیاوو سره جوړه شوې چې کلاینت یې ته اړتیا لري |
| کلاینت | د MCP Streamable HTTP ملاتړ وکړي، یا د stdio پله (bridge) |
| شبکه | له کلاینت ځایه اپلیکیشن ته HTTPS لاسرسی |
