# د MCP ستونزه‌شکنی

ډېرې د MCP ناکامۍ د ترتیب ستونزې دي، د سرور تېروتنې نه. له بهر څخه دننه خوا ته کار وکړئ: لومړی پای ټکی تایید کړئ، بیا token، بیا وړتیا، بیا څانګه.

## چټکه تشخیص

| نښه | احتمال لامل | حل |
| --- | --- | --- |
| کلاینت نشي نښلونې | غلط URL یا بندة شبکه | `https://<host>/mcp/business` وکاروئ، بهر ته لېږد (egress) خلاص کړئ |
| `/mcp/test` باندې `404` | سنډبکس غیر فعال دی | یوازې په local/testing کې د debug سره شتون لري |
| پر GET `405` | ترانسپورټ یوازې POST دی | په براوزر د پته بار سره یې مه ازموئ |
| `401` | ورک، غلط یا لغوه شوی token | پټ کوډ له ترتیباتو څخه بیا کاپي کړئ |
| `403 api_ability_denied` | وړتیا یا ژوندی پاڼې واک نشته | وړتیا او د پاڼې واک ورکړئ |
| `403 branch_scope_denied` | څانګه له محدودې بهر | یوه ورکړل شوې څانګه وکاروئ |
| `422 branch_required` | څو-څانګه اعتبارنامه پرته له څانګې | `branch_id` یا سرلیک ولېږئ |
| `429` | burst یا کوټه | `Retry-After` درناوی وکړئ |
| هېڅ افزار نه لیستېږي | لاسورکړه (handshake) ناکامه شوه | `Accept` او د JSON-RPC ځواب وکتئ |
| خالي پایلې | څانګه یا فلټرونه هر څه وباسي | څانګه یا د نېټو range پراخه کړئ |

## د تصدیق ناکامۍ

### 401 integration_credential_required

هېڅ token سرور ته نه دی رسېدلی، یا token د ادغام token نه دی.

- تایید کړئ چې سرلیک `Authorization: Bearer <token>` دی، د `Bearer` کلمه پشمول.
- تایید کړئ چې کلاینت په پله (bridge) کې له stdio څخه HTTP ته د تګ پر مهال سرلیکونه نه کموي.
- تایید کړئ چې `/mcp/business` غواړئ، نه `/api/v2`.

### 401 integration_credential_invalid

اعتبارنامه بېرته اخیستل شوې، سوداګري غیر فعاله ده، یا token له اعتبارنامې سره د بل کاروونکي پورې اړه لري.

- د اعتبارنامې حالت په ترتیباتو کې وګورئ.
- د سوداګرۍ subscription او حالت فعال تایید کړئ.
- که شک لرئ، اعتبارنامه وڅرخوئ؛ څرخول تل سم token جوړوي.

### 403 integration_membership_inactive

کارکوونکی جابور شوی یا غړیتوب یې لرې شوی دی. د یوه فعال کارکوونکي لپاره اعتبارنامه جوړه کړئ؛ د زاړه بېرته ژوندی کولو هېڅ لاره نشته.

## د واک (Authorisation) ناکامۍ

### 403 api_ability_denied

اعتبارنامه وړتیا نه لري، یا د کارکوونکي رول نور ور تر شا پروت پاڼې واک نه ورکوي.

1. ترتیبات پرانیزئ او تایید کړئ چې وړتیا په اعتبارنامه کې ټاکل شوې ده.
2. د کارکوونکي د لاسرسي پاڼه پرانیزئ او تایید کړئ چې د پاڼې واک ورکړل شوی دی.
3. کلاینت بیا بار کړئ؛ ناکامي په هره غوښتنه کې ارزول کېږي، نو د سمون وروستۍ نوې هڅه بس ده.

### 403 branch_scope_denied

غوښتل شوې څانګه د اعتبارنامې په ورکړل شویو سیټ کې نه ده، یا د همدې سوداګرۍ نه ده.

- له `/api/v2/context` څخه `branch_scope.allowed_branch_ids` ولولئ.
- له هغو یو id وکاروئ، یا د څانګې آرګومنت لرې کړئ ترڅو ډیفالټ کارول شي.
- نور id په دې تمه مه ازموئ چې یو به کار وکړي؛ دا د محدودې د ردېدو په توګه ثبتېږي.

### 422 branch_required

اعتبارنامه په څو څانګو محدودې ده او بلل هیڅ نوم نه درلود. د افزار په آرګومانونو کې `branch_id` ولېږئ یا د کلاینت په ترتیب کې `X-Business-Branch`.

## د نرخ د محدودیت ستونزې

### 429 api_burst_limit_exceeded

له یوې اعتبارنامې څخه په یوه دقیقه کې له 60 زیاتې غوښتنې. د `Retry-After` په تمه کښېنئ، بیا د غوښتنو کچه کمه کړئ. مرستیال چې د افزار په بللو کې څرخیږي، ژر یې ترلاسه کوي.

### 429 api_quota_exceeded

د ورځې یا میاشتې اجازه پای ته رسېدلې ده. له بدن (body) څخه `scope`، `period`، `limit`، `used` او `reset_at` ولولئ. انتخابونه:

- د بیا ټاکلو (reset) وخت په تمه کښېنئ.
- د polling کچه یا د پاڼې اندازه کمه کړئ.
- له مدیر څخه د لوړ پلان په اړه پوښتنه وکړئ.
- که د کوټې جلا والی مهم وي، ادغامونه په جوړیالانو ووېشئ.

## د ترانسپورټ ستونزې

| ستونزه | تشریح | حل |
| --- | --- | --- |
| پر GET یا DELETE 405 | سرور یوازې POST مني | د براوزر پر ځای MCP کلاینت وکاروئ |
| اړیکه ژر تړل کېږي | د پراکسي بافربندي یا وخت تېرېدل | د MCP لپاره بافربندي غیر فعاله کړئ |
| د ناستې تېروتنې | `MCP-Session-Id` نه لېږدول کېږي | د ناستو مدیریت کوونکی کلاینت یا پله وکاروئ |
| د JSON پر ځای HTML | `Accept: application/json` نشته | سرلیک ورزیات کړئ |
| محلي کار کوي، production نه | سنډبکس د رڼې اعتبارنامې پر وړاندې | د production اعتبارنامه وکاروئ |

## د افزار هغې پایلې چې ناسمې ښکاري

- **خالي لیست**: څانګه په غوښتل شوې موده کې ډاټا نلري، یا اعتبارنامه بلې څانګې ته محدوده ده.
- **`Purchase not found`**: id د لیدو وړ محدودې بهر دی، یا سند لرې شوی دی.
- **مقدارونه د متنوې په څېر ښکاري**: هغه decimal په توګه پارس کړئ؛ ځینې کلاینته JSON عددونه د متنوې په توګه ښیي.
- **د توکو نومونه په غلطه ژبه**: `language_code` ولېږئ؛ ډیفالټ د اپلیکیشن د locale تعقیبوي.

## د سرور د روغتیا تایید

1. `GET /api/v2/health` `{"data":{"status":"ok"}}` ستنوي.
2. `GET /api/v2/context` له هماغه token سره محدوده او کوټه ستنوي.
3. `tools/list` پنځه افزارونه ستنوي.
4. د `products` بلل د `per_page: 1` سره یوه کرښه ستنوي.

که ګام 2 کار وکړي او ګام 4 ناکام شي، ستونزه د افزار آرګومانونه دي، اړیکه نه.

## کله د ملاتړ (support) سره اړیکه ونیول شي

- د context پای ټکی بریالی وي، خو د واکونو له تایید وروسته هر افزار `403` سره ناکامېږي.
- افزار له ورکړل شوې محدودې بهر د بلې څانګې ډاټا ستنوي.
- کوټه پرته له غوښتنو پرمختګ کوي.
- سرور د یوه افزار لپاره په دوامداره توګه `500` ستنوي.

د اعتبارنامې نوم (هېڅکله token نه)، وخت، د افزار نوم، آرګومانونه او ستنېدلې د تېروتنې کوډ شامل کړئ.
